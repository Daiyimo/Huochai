# Everything 1.5 beta 升级可行性

核查日期：2026-09-03。对应火柴离线构建 `2026.09.03.1`。

本文保留升级前的评估快照。后续 `2026.09.03.2` 已实施升级，实际方案、服务适配及全盘测试结果见 [升级实施记录](everything-1.5-upgrade.md)。

结论：建议将 **官方签名的 Everything 1.5 x64 引擎 + 火柴 x86 界面 + 独立适配层** 作为下一阶段方案。基础查询协议已经实测可用，值得做可回退的试用版本；当前还不能作为直接替换 DLL 或 EXE 的升级交付。本次正式产物仅修复缓存与路径，仍使用原来的 1.4.1.1028 引擎。

## 组件与官方版本

| 组件 | 项目当前情况 | 官方情况 / 判断 |
| --- | --- | --- |
| `hc_engine.exe` | Everything 1.4.1.1028 x86，经过离线补丁 | 稳定版为 1.4.1.1032（2026-01-23） |
| 1.5 beta 引擎 | 未集成到正式包 | 1.5.0.1423b（2026-08-27），提供 x86、x64 |
| `Everything32.dll` | 77,824 字节，88 个导出 | 当日官方 SDK 的 x86 DLL 为 88,232 字节、89 个导出；新增 `Everything_MSIExitAndStopService` |

版本来源：[稳定版更新记录](https://www.voidtools.com/Changes.txt)、[1.5 beta 官方发布页](https://www.voidtools.com/forum/viewtopic.php?f=12&t=9787)。SDK 大小、导出与哈希为本次下载及本地文件的静态比较。

`Everything32.dll` 是客户端 IPC 封装，后台 EXE 才承担索引和检索工作。官方 DLL 未提供可用于比较的 FileVersion，不能把 EXE 的“1.5”当成 DLL 的版本号。仅替换 DLL 不会带来新索引引擎；新增的 MSI 服务退出接口对日常文件名检索没有直接收益。[官方 SDK 说明](https://www.voidtools.com/support/everything/sdk/)

## 实际验证

下载官方便携 ZIP 后保留原 EXE 字节，Windows `Get-AuthenticodeSignature` 对两种架构均返回 `Valid`，签发主体为 voidtools PTY LTD。

| 引擎架构 | EXE 大小 | SHA-256 |
| --- | ---: | --- |
| x86 | 4,257,960 | `679b2732ed7c441f4e1c761cda89fd65a2e5c48382cd86501055eb64d900bdff` |
| x64 | 5,138,088 | `81b4d05e84e61891ac043dd76e97de616af17adf53b2ee2fe984d8b0bbbfcc21` |

使用仓库的 `reverse/beta_probe.py` 和 **x86** 的 `test_engine_ipc.exe`，分别启动带唯一实例名的 x86 / x64 引擎，只索引三个测试文件，不安装服务。两个架构均通过：

- `sample-archive-001.zip`、`wholefilename:sample-archive-001.zip`、`sample 001`、`ext:zip sample` 均返回 1 条；不存在的文件返回 0 条。
- 中文文件名、含中文和空格的目录可检索。
- 重命名文件并显式重新扫描后，旧名称返回 0，新名称返回 1。
- 公共 `SAVE_DB` IPC 可以创建及刷新数据库；终止引擎、删除测试文件后，以只读模式重新启动仍能查到保存的记录，证明确实读取了缓存。
- x86 查询进程可以通过 IPC v1 与 x64 引擎通信，说明升级后台不要求先把现有界面改为 64 位。

这验证了协议和缓存行为，**没有验证现有 Everything32.dll 到命名实例的路由，也没有运行真实火柴界面、标准用户 NTFS 服务或百万文件性能测试**。文件夹变化通过显式 `-rescan-all` 验证，不能据此宣称自动增量监控已通过。测试中的 ZIP 是虚构命名的占位文件，非真实压缩包。

文件能否被检索首先取决于磁盘覆盖、索引就绪和查询链路。协议探针通过后，仍需验证服务及实际界面的完整调用路径。

可复现实验，先用 `python reverse/build.py --keep-workdir` 获得 x86 查询探针，然后指定下载解压的官方 EXE：

```powershell
python reverse/beta_probe.py --engine <x86目录>\Everything.exe --engine <x64目录>\Everything.exe --query <构建目录>\test_engine_ipc.exe --output <结果目录>\beta-probe.json
```

## 不能直接替换的原因

1. **官方服务验证签名。** 1.4.1.1030 和 1.5.0.1401a 开始增加服务连接验证，只接受 voidtools 签名的 Everything 客户端。当前 `build.py` 会改写引擎导入表、地址和资源，破坏原始签名；不能继续把这一处理套在新引擎上。应保留官方 EXE，在独立适配层处理启动参数与火柴接口。[1.4 更新记录](https://www.voidtools.com/Changes.txt)、[1.5 开发者发布记录](https://voidtools.com/forum/viewtopic.php?p=83240)
2. **当前路径与生命周期写死在旧布局。** `engine_entry.h` 的参数注入和托盘拦截依赖引擎加载 `hcg.dll`；`launcher.c` 的发现、退出及服务归属检查锁定本目录 `hc_engine.exe`。保留签名的新引擎需要外部传入 `-config`、`-db`、`-startup` 和实例名，使用官方配置控制托盘，并让启动器跟踪真实后台路径/PID。不要沿用未经验证的服务安装、删除假设。
3. **命名实例需要查询适配。** 当日官方 SDK 源码使用固定窗口类 `FindWindow(EVERYTHING_IPC_WNDCLASS, 0)`，当前接口没有设置实例名的导出。隔离运行时需要由兼容的 x86 SDK 适配层把请求路由到本应用实例；新测试按 PID 选择窗口，因此不能冒充现有 DLL 已经完成适配。否则可能查询到用户另装的 Everything。
4. **数据库和回退必须隔离。** 1.5 官方记录说明新数据库版本不能由旧版本读取。建议使用 `Data\Index-1.5` 和独立 INI，保留旧缓存；迁移只操作副本，回退时重新选用 1.4 配置与数据库。[数据库变化记录](https://voidtools.com/forum/viewtopic.php?p=83240)
5. **打包和离线验收要改变。** 当前构建从固定 Git 二进制提取引擎，外层启动会按哈希修复手工替换的文件。若把官方引擎放在子目录，`package()` 还需把这些程序文件纳入递归校验与修复，而非当作只初始化一次的数据。当前 URL 残留清理/拒绝层验收也不能直接用于保持签名的 EXE；关闭更新、服务器及不需要的插件后，应实测联网行为，不能只凭配置宣称完全离线。

## 对全盘文件检索的收益

最贴近本项目的是**启动后先搜索缓存、后台继续追赶磁盘变化**，可以减少启动后等待索引更新的时间。官方同时说明，极新的文件变化可能要等后台更新结束才出现，必要时仍会重建。[后台更新说明](https://www.voidtools.com/forum/viewtopic.php?f=12&t=9790)

1.5 还改进查询、多条件搜索、属性索引、忽略标点/空白和 FAT 索引。对多盘、大索引和移动盘值得评估，但这些官方能力不等于现有火柴界面自动获得相应按钮或交互；文件名检索也不等同于搜索 ZIP 内部文件或压缩包正文。[搜索改进](https://www.voidtools.com/forum/viewtopic.php?f=12&t=9795)、[索引改进](https://www.voidtools.com/forum/viewtopic.php?f=12&t=9796)

建议先做可切换的 1.5 x64 试用后端，验收以下实际结果后再设为默认：

- 标准账户配合官方服务，覆盖全部目标 NTFS 磁盘；非 NTFS 和移动盘有明确纳入策略。
- 查询通用测试文件、完整路径、多个关键词、中文、超长路径及多盘重名文件；完整文件名命中优先，文件操作针对正确路径。
- 新建、下载完成、改名、移动、删除、断盘及重接后结果及时更新；区分“未找到”和“索引尚未更新”。
- 对比相同数据集的冷启动、热启动可搜索时间、查询 P50/P95、空闲 CPU、内存和磁盘写入量。
- 服务权限失败、并存的 Everything、退出中断、旧缓存恢复及回退到 1.4 均通过。

这些工作主要在适配、索引完整性和运行可靠性上。若只想尽快补齐稳定版修复，1.4.1.1032 也可作为过渡，但同样需要保留签名并处理新服务约束，不是替换一个 DLL 就能完成。
