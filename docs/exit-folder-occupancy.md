# 退出后的目录占用修复

> 历史集成实验记录。项目现以源码和技术分析为主，相关二进制不再分发；现行验证方式见 [构建说明](build.md)。

适用版本：`2026.09.03.4`。

## 原因

旧启动器将 `APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP` 指向便携目录。由火柴启动的第三方应用继承了这些路径，却可以独立于火柴继续运行，因此其缓存句柄可能在火柴退出后仍占用该目录。

## 修复

- 外部应用继承调用者原本的环境变量，使用正常的数据目录。
- 火柴自身的配置、便签、索引和临时文件继续使用便携路径；`GetTempPathW/A` 适配仅对受控模块生效。
- 保留旧第三方数据，不覆盖系统目录中的配置，也不强行结束外部应用或关闭其文件句柄。

## 验证与使用

回归覆盖七种进程启动入口的环境继承，并使用独立测试进程持有缓存文件句柄，验证火柴退出后可以移动整个便携目录，且原有数据保持不变。

旧版本启动的外部应用需要正常退出并重启才能使用新环境。如果外部程序直接打开便携目录内的文件，或将其设为工作目录，仍需等待它释放占用。
