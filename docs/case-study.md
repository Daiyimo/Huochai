# 技术解析

## PE 补丁与导入表重定向

补丁先识别固定输入，再根据 PE 结构定位字段，避免按任意偏移修改未知版本。路径补丁还要同步处理地址操作数与 ASLR 重定位；字符串修改应保持固定字段长度，不侵入相邻数据。

独立 demo 将自编程序的 `KERNEL32.dll` 导入描述符重定向到自编的 `demohook.dll`，重新计算 PE 校验和，并确认文件长度未变化。这里演示的是静态导入表重定向，不是跨进程注入。

## API hook 与调用约定

演示 DLL 只替换 `GetTickCount` 的返回值，其余导入转发给原系统 DLL。补丁样例实际调用 API，检查返回值已由演示实现提供。固定返回值仅用于教学断言，不用于正常应用计时。

历史集成代码还展示 A/W 接口、`GetProcAddress` 动态查找及 x86 stdcall 栈清理。转发导出需要检查目标确实存在；仅成功生成 DLL 不足以证明加载与调用正确。

## URL、业务域名与资源清洗

`policy.py` 保留 `BARE_DENYLIST`、裸域名、ASCII、UTF-16 和 Base64 检测样例，展示从命中位置到修改结果的过程。名单是特定实验样本的匹配集合，不是恶意域名判断，也不能作为确认实际联网的证据。

定长补丁使用不改变长度的替换与填充，避免将 SQL 或格式字符串提前截断；XML 等结构化文本则检查修改后仍能解析。回归覆盖重叠命中、偏移变化、邮箱和源码文件名误报。

操作完整 PE 时先用 `url_hits` 确认地址，再将命中偏移通过 `only` 参数交给清洗器。不能把所有形似 Base64 的字符串直接抹除，否则可能破坏系统 API 名称或字符表。独立 demo 还检查清洗前后导入函数名保持一致。

版权与许可证文件由 `license_notices.py` 单独复制和逐字节校验；即使含有域名，也不会被清洗。保留教学名单不等于取得删除第三方署名或限制性条款的权限。

## 验证必须覆盖实际调用路径

历史实验曾出现 SDK 查询通过、界面查询失败：原界面直接发送 IPC v1，没有走 SDK。因此回归需要覆盖真正使用的窗口查找、请求构造与回包路径，而不是用邻近接口替代验证。

独立 demo 可由公开源码直接构建。历史集成实验使用单独准备的固定输入，记录作为技术案例保留，不构成二进制分发或完整原软件源码。

## 功能复现与字节复现

功能复现检查调用结果、文件布局和生命周期；字节复现要求相同输入与环境产生完全相同的哈希。两者分别报告，不能用一次功能通过代替确定性构建。

本项目为 MSVC 链接统一启用 `/Brepro`，独立 demo 已验证连续构建的三个 PE 逐字节一致。完整集成包还包含 NSIS、输入文件时间和资源处理，须使用 Benchmark 重复构建工具单独确认，不能从 demo 结果推断。
