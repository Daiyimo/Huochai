# Everything 1.5 升级说明

官方签名的 Everything `1.5.0.1423b` x64 引擎已接入火柴 x86 界面。升级自 `2026.09.03.2` 开始，界面直接查询适配在 `2026.09.03.3` 补齐。

## 实现

- `Engine/Everything.exe` 保留官方文件字节与签名，固定输入见 [依赖说明](../reverse/vendor/README.md)。
- `Everything32.dll` 与主程序通过 `hce.dll` 查找本目录的独立实例，同时校验窗口所属进程路径。
- `hc_engine.exe` 兼容原界面的启动和服务控制请求，使用明确命名的 Windows SCM 接口管理本目录服务。
- 1.5 的配置和数据库保存在 `Data/Index-1.5`，旧配置与数据库保留用于回退。
- 外层启动器递归校验、释放和修复引擎文件，并管理本目录引擎的退出。

原界面直接通过窗口消息发送 IPC v1 查询，并未使用 SDK 的查询函数。仅适配 SDK 会出现后台可查、界面无结果的问题，因此两条调用路径必须同时接入独立实例。[官方 IPC 示例](https://www.voidtools.com/support/everything/sdk/ipc_c_example/)

开发阶段发现，官方安装命令的实例参数不能代替明确的服务名，曾意外影响默认服务；当时已恢复。最终实现改用显式命名的 SCM 接口，回归核对默认服务配置保持不变。

## 验证

回归覆盖实际 SDK 和原程序查询代码、中文及多条件检索、文件增删改监控、实例隔离、索引保存与重新加载、旧数据保留，以及打包修复。另验证了非管理员引擎通过独立签名服务检索 NTFS 分区。

这些验证不等同于完整桌面操作回归；移动盘拔插、注销和关机等场景仍需单独验证。1.5 属于 beta，版本状态见 [官方发布记录](https://www.voidtools.com/forum/viewtopic.php?f=12&t=9787)。

## 升级与回退

退出程序并备份 EXE 和同级数据目录，再替换新版 EXE。首次升级到 1.5 会建立独立索引，首次安装服务可能需要管理员授权。

回退到 `2026.09.03.1` 或更早的 1.4 版本时，旧引擎读取 `Data/Index`，不会读取 1.5 数据库。服务清理受账户权限限制，失败原因记录在 `Data/offline.log`。
